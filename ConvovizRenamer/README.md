# ConvovizRenamer

Утилита для автоматического приведения Markdown-файлов, экспортированных из **Convoviz**, к удобным именам на основе YAML-свойства `aliases`.

Утилита обрабатывает дерево каталогов, переименовывает Markdown-файлы, обновляет `title` в YAML frontmatter и исправляет ссылки в соответствующих `_index.md`.

## Возможности

* Поиск всех `.md`-файлов в каталоге и его подкаталогах.
* Игнорирование файлов `_index.md`.
* Получение первого элемента YAML-списка `aliases`.
* Использование `aliases[0]` в качестве нового имени файла.
* Сохранение кириллицы и других допустимых Unicode-символов.
* Удаление символов, недопустимых в имени файла Windows.
* Удаление пробелов и точек в конце имени.
* Обновление YAML-свойства `title`.
* Автоматическое исправление ссылок в `_index.md`.
* Обнаружение конфликтов имён.
* Отдельная обработка каждого каталога.
* Подсчёт результатов обработки.

## Пример

До обработки:

```text
2026/
├── _index.md
├── AI.md
└── untitled (1).md
```

Содержимое одного файла:

```yaml
---
title: "Старое название"
aliases:
  - "Движок AI модели"
---
```

После обработки:

```text
2026/
├── _index.md
├── Движок AI модели.md
└── Сохранение проекта как шаблон.md
```

Frontmatter:

```yaml
---
title: "Движок AI модели"
aliases:
  - "Движок AI модели"
---
```

Ссылки в `_index.md` также исправляются:

```markdown
[Старое название](AI.md)
```

становится:

```markdown
[Старое название](Движок%20AI%20модели.md)
```

Текст ссылки при этом не изменяется.

## Требования к Markdown-файлам

Утилита ожидает YAML frontmatter в начале файла:

```yaml
---
title: "Название"
aliases:
  - "Название файла"
  - "Другой alias"
---
```

В качестве имени используется только первый элемент `aliases`.

Например:

```yaml
aliases:
  - "Главное название"
  - "Альтернативное название"
```

приведёт к имени:

```text
Главное название.md
```

## Обработка `title`

После успешного переименования значение `title` синхронизируется с первым `aliases`:

```yaml
aliases:
  - "Новое название"
```

становится:

```yaml
title: "Новое название"
aliases:
  - "Новое название"
```

Если `title` отсутствует, утилита добавляет его в YAML frontmatter:

```yaml
---
title: "Новое название"
aliases:
  - "Новое название"
---
```

Если YAML frontmatter отсутствует или файл не содержит `aliases`, файл пропускается.

## `_index.md`

В каждом каталоге `_index.md` рассматривается независимо.

Это означает, что обработка:

```text
2026/
    _index.md
    file1.md
    file2.md

2025/
    _index.md
    file3.md
```

выполняется отдельно для `2026` и `2025`.

После переименования ссылки на старые имена файлов заменяются на новые.

Поддерживается URL-кодирование символов, имеющих специальное значение в Markdown URL:

```text
пробел → %20
#       → %23
?       → %3F
%       → %25
+       → %2B
(       → %28
)       → %29
```

Unicode-символы, включая кириллицу, не кодируются.

## Конфликты

Утилита не перезаписывает существующие файлы.

Например, если существуют:

```text
A.md
B.md
Test.md
```

и:

```text
A.md → Test.md
```

операция будет пропущена с сообщением:

```text
[CONFLICT] Файл уже существует:
           ...\Test.md
           ← ...\A.md
```

Также обнаруживаются конфликты между самими операциями:

```text
A.md → Test.md
B.md → Test.md
```

В этом случае оба переименования отменяются.

## Порядок обработки

Для каждого каталога выполняются два основных прохода.

### Первый проход

Утилита:

1. читает `aliases`;
2. формирует новое имя;
3. проверяет корректность имени;
4. проверяет существование целевого файла;
5. собирает список операций.

Файлы на этом этапе не изменяются.

### Второй проход

После проверки всех операций:

1. выполняется `File.Move`;
2. обновляется `title`;
3. сохраняется информация об успешном переименовании;
4. после обработки всех файлов обновляется `_index.md`.

Таким образом, `_index.md` изменяется только для реально выполненных переименований.

## Результат обработки

Метод:

```csharp
RenameResult Rename(string rootDirectory)
```

возвращает статистику:

```csharp
public sealed class RenameResult
{
    public int Total { get; internal set; }

    public int Renamed { get; internal set; }

    public int AlreadyCorrect { get; internal set; }

    public int Skipped { get; internal set; }

    public int Conflicts { get; internal set; }

    public int Errors { get; internal set; }

    public int IndexFilesUpdated { get; internal set; }
}
```

Например:

```text
Total:              125
Renamed:             87
AlreadyCorrect:      21
Skipped:              9
Conflicts:             5
Errors:               3
IndexFilesUpdated:   42
```

## Сообщения в консоли

Утилита выводит сообщения с различными статусами:

```text
[OK] AI.md → Движок AI модели.md
```

```text
[SKIP] Alias не найден: ...\file.md
```

```text
[CONFLICT] Файл уже существует:
           ...\Test.md
           ← ...\file.md
```

```text
[ERROR] Не удалось переименовать:
        ...\file.md
        → ...\Test.md
        ...
```

```text
[INDEX] ...\_index.md
```

## Ограничения

Утилита использует упрощённый разбор YAML и рассчитана на структуру Convoviz, а не на произвольный YAML-документ.

В частности, ожидается стандартный вид:

```yaml
---
title: "Название"
aliases:
  - "Название"
---
```

Сложные YAML-конструкции, многострочные значения и вложенные структуры специально не разбираются.

## Безопасность обработки

Утилита:

* не удаляет исходные файлы;
* не перезаписывает существующие файлы;
* не изменяет `_index.md`, если переименований не произошло;
* не меняет отображаемый текст Markdown-ссылок;
* пропускает файлы с отсутствующим или некорректным `aliases`.

При этом обновление `title` выполняется после физического переименования файла. Поэтому при ошибке изменения `title` файл уже может иметь новое имя, а ошибка будет отражена в `RenameResult.Errors`.

## Назначение

Основной сценарий использования — обработка экспорта Convoviz перед переносом Markdown-базы в систему, использующую имена файлов как человекочитаемые идентификаторы, например Obsidian.
