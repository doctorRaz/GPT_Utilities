# Archivist

Утилита для обработки Markdown-файлов, экспортированных с помощью **[chatgpt-exporter](https://github.com/pionxzh/chatgpt-exporter)**.

Archivist импортирует разговоры из ZIP-архивов экспорта ChatGPT, организует их в каталоге назначения, синхронизирует существующие файлы и поддерживает обслуживание уже созданного vault.

## Возможности

- Обработка последнего ZIP-архива или всех архивов экспорта ChatGPT.
- Распаковка архивов во временный каталог.
- Поиск и обработка экспортированных Markdown-файлов.
- Чтение и запись YAML front matter.
- Определение даты создания и изменения разговора.
- Организация файлов по каталогам `YYYY/MM-MMMM`.
- Нормализация имён файлов:
  - символ `#` заменяется пробелом, чтобы не создавать проблемы с синтаксисом ссылок Obsidian;
  - последовательности пробельных символов сворачиваются в один пробел;
  - пробелы в начале и конце имени удаляются;
  - символы Unicode, включая кириллицу, сохраняются;
  - символ `_` не заменяется на пробел.
- Синхронизация с уже существующими Markdown-файлами.
- Сравнение метаданных и обновление файла, если экспортированная версия новее.
- Идентификация разговора по `conversation_id` с использованием `chat_link` как fallback.
- Защита от создания дубликатов.
- Сохранение времени изменения файла (`LastWriteTime`).
- Построение и обновление навигационных индексов.
- Режим обслуживания существующего vault без обработки ZIP-архивов.

## Принцип работы

В обычном режиме Archivist:

1. Находит ZIP-архивы в исходном каталоге.
2. По умолчанию выбирает последний архив; с `--all` обрабатывает все найденные архивы.
3. Распаковывает выбранный архив во временный каталог.
4. Находит Markdown-файлы экспорта.
5. Читает YAML front matter и формирует `ChatMetadata`.
6. Нормализует имя файла.
7. Определяет каталог назначения по `create_time`.
8. Проверяет существующий файл и сравнивает метаданные.
9. Копирует новый файл или обновляет существующий, если экспортированная версия актуальнее.
10. Обновляет навигационный индекс.

## Нормализация имени файла

Нормализация применяется к имени Markdown-файла, а не к его содержимому.

Текущие правила:

- `#` заменяется пробелом;
- последовательности пробельных символов заменяются одним пробелом;
- ведущие и завершающие пробелы удаляются;
- `_` сохраняется без изменений;
- Unicode-символы не удаляются и не транслитерируются.

Например:

```text
My_Chat_#_Test.md
```

становится:

```text
My_Chat_ Test.md
```

## `conversation_id` и `chat_link`

`conversation_id` является значением модели `ChatMetadata` и поддерживает round-trip через YAML front matter.

При чтении YAML:

1. если присутствует `conversation_id`, используется именно он;
2. если `conversation_id` отсутствует, но `chat_link` содержит идентификатор разговора, он вычисляется из `chat_link`;
3. если оба значения отсутствуют, `ConversationId` остаётся `null`;
4. если `conversation_id` и `chat_link` противоречат друг другу, приоритет имеет явно записанный `conversation_id`.

При записи YAML:

- если `ConversationId` известен, он записывается как `conversation_id`;
- если `ConversationId` не задан, но из `chat_link` можно получить идентификатор, он также записывается как `conversation_id`;
- если идентификатор получить невозможно, `conversation_id` не добавляется.

`chat_link` при этом сохраняется как отдельное поле YAML.

## Метаданные

Для работы с экспортированными разговорами используется типизированный класс `ChatMetadata`.

Поддерживаются, в частности, следующие поля YAML front matter:

- `title` — название разговора;
- `aliases` — альтернативные имена;
- `tags` — теги;
- `create_time` — время создания разговора;
- `update_time` — время последнего изменения;
- `date_export` — дата экспорта;
- `chat_link` — ссылка на разговор ChatGPT;
- `conversation_id` — идентификатор разговора.

`create_time` является обязательным для обработки файла. Остальные поля могут отсутствовать в зависимости от исходного экспорта.

## Структура каталога

Каталог назначения формируется по времени создания разговора в UTC. Используется стабильное англоязычное имя месяца:

```text
Output/
├── 2026/
│   ├── 08-August/
│   │   ├── Conversation 1.md
│   │   └── Conversation 2.md
│   ├── 09-September/
│   │   └── ...
│   └── ...
└── ...
```

## Синхронизация

Archivist не просто копирует экспортированные файлы. Перед записью он проверяет, существует ли соответствующий файл в каталоге назначения, и сравнивает метаданные.

Это позволяет повторно запускать импорт без бесконтрольного создания копий одного и того же разговора. При наличии более новой экспортированной версии существующий Markdown-файл обновляется.

## Индексы

В обычном режиме Archivist поддерживает навигационные индексы при синхронизации файлов.

Для уже существующего vault доступен отдельный режим обслуживания, который нормализует существующие имена файлов и перестраивает `_index.md`.

## Режим обслуживания

Режим `--maintenance` предназначен для обслуживания уже обработанного каталога.

В этом режиме ZIP-архивы не обрабатываются. Archivist:

- проходит по существующему vault;
- нормализует имена файлов по текущим правилам;
- обновляет/перестраивает `_index.md`.

Режим удобен после изменения правил нормализации или при необходимости восстановить навигационные индексы.

## Командная строка

Основной синтаксис:

```text
GPT_Archivist -s <каталог> -d <каталог> [опции]
```

Параметры:

- `-s`, `--source <каталог>` — каталог с ZIP-архивами экспорта ChatGPT. Каталог должен существовать.
- `-d`, `--destination <каталог>` — каталог назначения. Если отсутствует, будет создан.
- `-p`, `--pattern <маска>` — маска ZIP-файлов. По умолчанию `*.zip`.
- `-m`, `--maintenance <каталог>` — обслуживание существующего vault без обработки архивов.

Опции:

- `-a`, `--all` — обработать все ZIP-архивы. По умолчанию обрабатывается только последний.
- `-h`, `--help`, `/?` — показать справку.

Примеры:

```text
GPT_Archivist -s "D:\GPT\Archives" -d "D:\GPT\Unpacked"
GPT_Archivist -s "D:\GPT\Archives" -d "D:\GPT\Unpacked" -a
GPT_Archivist --source "D:\GPT\Archives" --destination "D:\GPT\Unpacked" --all
GPT_Archivist -s "D:\GPT\Archives" -d "D:\GPT\Unpacked" -p "*.zip"
GPT_Archivist --maintenance "D:\GPT\Unpacked"
GPT_Archivist -m "D:\GPT\Unpacked"
```

При ошибках обработки приложение завершает работу с ненулевым кодом возврата.
